01 · CONSTRUIR O CONCEITO

As duas VLANs funcionam isoladamente

01

Um host 192.168.10.10/24 na VLAN 10 acessa vizinhos locais. Um servidor 192.168.20.20/24 na VLAN 20 também funciona localmente. Para comunicar entre eles, não basta um cabo entre os switches. É necessário um caminho de camada 3, endereços de gateway e políticas que permitam o serviço.

Neste laboratório, os gateways são 192.168.10.1 e 192.168.20.1. O desenho usa endereços didáticos e não deve ser aplicado a uma rede de produção sem projeto. As atividades podem ser realizadas em simulador.
02 · CONSTRUIR O CONCEITO

Access e trunk descrevem funções de porta

02

Uma porta access atende o tráfego de dados de uma VLAN no caso básico. Um trunk transporta tráfego de múltiplas VLANs por um enlace, normalmente com identificação IEEE 802.1Q. A lista de VLANs permitidas e a VLAN nativa devem ser coerentes nas pontas; há particularidades de plataforma e configuração.

Conectar um PC a uma porta de outra VLAN não move a sub-rede do host automaticamente. Deixar de permitir uma VLAN num trunk pode interromper parte do caminho mesmo que o link físico esteja ativo. VLAN não é firewall: a segurança entre zonas exige políticas explícitas.
03 · CONSTRUIR O CONCEITO

O quadro muda; o destino IP permanece

03

O host compara destino e máscara. Como 192.168.20.20 está fora de 192.168.10.0/24, consulta sua rota e usa o gateway 192.168.10.1. Após resolver o MAC do próximo salto por ARP, envia o pacote em um quadro destinado ao MAC dessa interface do gateway.

O roteador ou switch L3 remove o cabeçalho de enlace de entrada, consulta rotas e encapsula o pacote no enlace de saída. No exemplo sem NAT, os IPs de origem e destino permanecem; TTL e checksum IPv4 são atualizados. Os endereços MAC mudam entre os enlaces.
04 · CONSTRUIR O CONCEITO

A decisão usa o prefixo mais específico

04

Uma rota diretamente conectada aparece quando a interface correspondente está operacional no contexto da plataforma. Entre rotas de prefixos diferentes que correspondem ao destino, vence a de prefixo mais longo. Uma rota default /0 é usada quando não existe uma rota mais específica aplicável.

Isso não é o mesmo que escolher sempre o menor custo entre todas as rotas. Primeiro ocorre a correspondência de prefixo; a seleção entre alternativas de um mesmo prefixo depende de origem, preferência e métricas. O caminho de retorno também precisa existir.
05 · CONSTRUIR O CONCEITO

Observe antes de configurar

05

Em Cisco IOS/IOS XE de laboratório, use show vlan brief, show interfaces trunk, show interfaces switchport, show ip interface brief e show ip route para conferir o plano. No host Windows, ipconfig /all e route print mostram parâmetros locais; no Linux, ip address e ip route.

A ordem de verificação é: enlace e porta; VLAN de acesso; transporte da VLAN; interface L3; máscara e gateway do host; rotas de ida e retorno; políticas; serviço. Comandos e sintaxe variam conforme o equipamento. Não desative controles de segurança como forma de diagnóstico.
EXPERIÊNCIA INTERATIVA

Teste, explique e compare

Altere os parâmetros ou avance pelas etapas. Registre a previsão antes de consultar o resultado.

Caso: 192.168.10.10/24, gateway .10.1 → servidor 192.168.20.20/24, gateway .20.1; HTTPS permitido no cenário correto. O simulador aplica uma causa conhecida por vez.

Entregável do laboratório

  1. Registre o cenário e uma previsão.
  2. Execute ao menos três variações e copie as evidências.
  3. Explique o resultado com o conceito da aula.
  4. Descreva uma limitação do modelo e o próximo teste numa rede real.
Critérios de conferência

Use parâmetros explícitos, cálculos ou etapas coerentes e uma conclusão proporcional à evidência. Compare seu resultado com as explicações do laboratório, sem tratar uma simulação como medição real.

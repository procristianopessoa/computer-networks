O QUE VOCÊ VAI DOMINAR

O conceito precisa explicar uma decisão

01 · CONSTRUIR O CONCEITO

Mesmo número de endereços para todos?

01

Uma rede-base 192.168.20.0/24 precisa atender grupos com 100, 50 e 20 interfaces, já incluindo os gateways. Dar um /25 a cada grupo consumiria 384 endereços, mais do que o /24 disponível. VLSM permite selecionar blocos distintos dentro de um mesmo plano.

O total de interfaces não basta: os blocos precisam ter tamanho potência de dois, alinhamento correto e ficar inteiramente dentro da rede-base. Reservas de crescimento são requisitos e devem entrar no dimensionamento antes de alocar.
02 · CONSTRUIR O CONCEITO

Escolher bits de host

02

Para LANs convencionais, encontre o menor h tal que 2^h−2 seja maior ou igual à demanda de interfaces. O prefixo é 32−h. Cem interfaces exigem /25 (126 utilizáveis); cinquenta, /26 (62); vinte, /27 (30). O cálculo pressupõe que o gateway já foi contado.

Não arredonde a demanda para uma máscara por semelhança visual. Trinta e uma interfaces não cabem num /27, embora o bloco tenha 32 endereços totais. O /31 é um caso de ponto a ponto e não é uma alternativa para uma LAN com dois usuários e um gateway.
03 · CONSTRUIR O CONCEITO

Do maior bloco para o menor

03

Ordene as demandas por tamanho para simplificar a alocação e evitar fragmentação desnecessária. No exemplo: 192.168.20.0/25 ocupa .0–.127; 192.168.20.128/26 ocupa .128–.191; 192.168.20.192/27 ocupa .192–.223. Os intervalos são disjuntos e estão contidos no /24.

A ordem decrescente é uma estratégia prática, não uma lei do protocolo. Um projeto válido pode ter outra organização quando preserva os limites dos blocos. Sempre verifique o alinhamento do endereço inicial com o tamanho escolhido.
04 · CONSTRUIR O CONCEITO

Documentar o que sobrou

04

A faixa .224–.255 permanece livre e corresponde a 192.168.20.224/27. O plano aloca 224 dos 256 endereços da base. As capacidades utilizáveis dos três grupos somam 218, mas a demanda inicial soma 170. Não confunda total alocado, capacidade utilizável, demanda e reserva.

Registre finalidade, rede/prefixo, máscara, faixa, broadcast, gateway, VLAN, responsável e reserva. Uma tabela de endereços não aplica segmentação nem políticas sozinha. DHCP, interfaces L3, rotas e controles precisam refletir o plano.
05 · CONSTRUIR O CONCEITO

Agregar exige cuidado

05

CIDR também permite representar blocos contíguos e alinhados por um prefixo menos específico. A base /24 pode resumir os endereços desse local quando a topologia e a responsabilidade pelo bloco permitem. Uma sumarização que inclua redes de outro destino pode encaminhar tráfego para o lugar errado.

Para aceitar um plano, confirme: cada grupo cabe; não há sobreposição; nenhuma sub-rede excede a base; os endereços de gateway são válidos; a reserva é consciente. O planejador usa LANs convencionais de /30 ou maiores e uma base /16 a /30 para manter o exercício manejável.
EXPERIÊNCIA INTERATIVA

Teste, explique e compare

Altere os parâmetros ou avance pelas etapas. Registre a previsão antes de consultar o resultado.

Inclua o gateway e a reserva acordada em cada demanda. Modelo de LAN convencional, prefixos /30 ou maiores; base /16 a /30; até 16 grupos.

Entregável do laboratório

Critérios de conferência

Use parâmetros explícitos, cálculos ou etapas coerentes e uma conclusão proporcional à evidência. Compare seu resultado com as explicações do laboratório, sem tratar uma simulação como medição real.
